# Chapter 1 – Project Elements and Schedule

## 1.1 Project Components

Your project will be assessed through two major components.

### 1. Creative Piece (35%)

The **Creative Piece** is the central outcome of the project.

Examples include:

- Software application
- Video game
- Immersive environment
- Mobile app
- Website
- Database system
- Scientific investigation
- Media production project

If the project involves research:

- Experimental protocols
- Assessment scripts
- Raw data (where possible)

should be submitted.

The project must contain a **clearly identifiable Creative Piece**, which represents the main practical output.

### Demonstration Requirement

You must also submit a **10-minute demonstration video** that includes:

- Slides explaining the project
- Explanation of methodology
- Demonstration of the product

---

### 2. The Report (65%)

The report describes the **project and its outcomes**.

Minimum requirements include:

- Description of the problem
- Literature review
- Description of the solution
- Critical evaluation

**Expected length:**  
**8,000 – 14,000 words**



---

# Chapter 2 – Showcase Guidelines

## 2.1 Introduction

Students must prepare a **Project Showcase video**.

- Length: **10 minutes ± 2 minutes**
- Submitted with the **Creative Piece**

The video normally includes:

- Explanation of the project
- Discussion of the supporting code
- Demonstration of the Creative Piece

---

## 2.2 Slides and Talk

The presentation should be **short and concise**.

Recommended:

- **Maximum ~5 minutes speaking**
- **Maximum ~5 slides**

The talk should address:

- The **central problem**
- **Existing systems or research**
- **Techniques used**
- **Evidence that the solution works**
- **Conclusions and lessons learned**

The audience is assumed to be **knowledgeable experts in computing**.

---

## 2.3 Demonstration

The demonstration should show the **Creative Piece functioning**.

Important considerations:

- Ensure the software runs correctly
- Prepare suitable hardware if needed
- Demonstrate key features clearly

Examiners expect the product to **run without technical issues**.

## 3.1 Introduction

---

## 3.2 Report Formatting

The report must comply with university standards.

### Format Requirements

- Must be submitted as a **PDF**
- Must include a **title page**


### Required Preamble Pages

Before Chapter 1 the report must include:

- Abstract
- Acknowledgements
- Ethics declaration
- Table of contents
- List of figures

---

### Text Formatting

Main text should use:

- **12pt Times New Roman**
- **1.5 line spacing**
- Numbered chapters and sections

Page numbering:

- Roman numerals for preliminary pages
- Arabic numerals starting at **Chapter 1**

---

### Figures and Tables

- Must be centred
- Must have numbered captions
- Must be referenced in the text

Example:

```

Figure 3.1 shows...
Table 3.1 presents...

```

---

### Equations

Equations must:

- Be centred
- Be numbered per chapter

Example numbering:

```

(1.1), (1.2)
(2.1), (2.2)

```

Example:

```

RMSE = sqrt( (1/N) Σ (xi − mi)^2 )

```

---

### Bullet Points and Lists

Lists should be **indented consistently**.

---

### Footnotes

Footnotes and endnotes **should not be used**.

---

### Referencing

The report must use the **Harvard referencing style**.

Examples:

- (Britch, 2003)
- (Britch and Costen, 2005)
- (Britch et al., 2007)

All citations must appear in the **reference list**.

---

### Quotations

Quotations should be **avoided where possible**.

If necessary:

- Short quotes → inline
- Long quotes → block format

All quotations must be **referenced properly**.

## 4.2 Positives and Negatives

### 4.2.1 Common Errors to Avoid


- Using first-person language
- Incorrect grammar
- Confusing similar words
- Misusing abbreviations

Examples:

- data is plural
- avoid "essentially"
- use **decimal points correctly**

---

### 4.2.2 The Ideal project Will

A strong project should:

- Present **clear arguments**
- Include **critical literature analysis**
- Identify and solve project problems
- Demonstrate **self-reflection**
- Suggest **future work**
- Show **effective time management**
- Be written in **clear academic English**

---

# 4.3 Submission FAQs

Common questions include:

### Using figures from papers
Allowed if properly **referenced and credited**.

### Similarity scores
Boilerplate text (references, declarations) may increase similarity but is normally acceptable.

### Online deployed systems
Provide:

- Code
- Executable
- URL if applicable

### Large datasets
Code alone may be acceptable if datasets are too large.

### Word count
Recommended range:

**8,000 – 14,000 words**

This is not a strict limit but exceeding it may affect style marks.
